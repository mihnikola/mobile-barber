## 0.1 How to build & run

Native modules (Firebase, Google/Apple sign-in) → **Expo Go does not work**; a native build is required. `android/` and `ios/` are not in git — they are generated by `expo prebuild` (CNG).

**Required local files (gitignored, get from team / Firebase console):**
| File | Needed for | Status on this PC (2026-11-12) |
|---|---|---|
| `.env` (`EXPO_PUBLIC_API_URL`) | API base URL | ✅ present |
| `firebase/google-services.json` | Android build | ❌ **missing** — Firebase console → project → Android app `fta.barber.app` → download |
| `firebase/GoogleService-Info.plist` | iOS build | ✅ present |

**A) Local Android debug build (recommended for regression testing; live reload via Metro)**
Machine check: JDK 17 ✅, Android SDK `C:\Android\sdk` (platforms 35/36, NDK 27) ✅, adb ✅, no emulator installed → use a physical phone with USB debugging.
```bash
npm install                 # after switching branches
adb devices                 # phone must be listed as "device"
npm run android             # = expo run:android → prebuild + gradle debug build + install + Metro
```
First build takes 10–20 min; later runs are incremental. After that, only `npx expo start` is needed while the app is installed (JS changes hot-reload). If native config changes: `npx expo prebuild --clean` then `npm run android`.

**B) EAS cloud build (Android or iOS; iOS only possible this way on Windows)**
```bash
npx eas-cli login           # account with access to org "fusion-tech-agency"
npx eas-cli build -p android --profile development   # APK
npx eas-cli build -p ios --profile production        # iOS (needs Apple credentials on EAS)
```
- EAS uploads the local working copy, so branch `claude` can be built **without pushing**.
- `.env` and `firebase/` are gitignored → not uploaded. EAS must have env vars `EXPO_PUBLIC_API_URL`, `GOOGLE_SERVICES_JSON`, `GOOGLE_SERVICE_INFO_PLIST` configured (app.config.ts reads the last two).
- The `development` profile is **not** a dev-client build (`expo-dev-client` isn't installed) → the APK contains a JS snapshot and does not connect to Metro.
- `npm run build:apk`, `build:ios`, `submit:android` use global `eas`; it is not installed globally here → use `npx eas-cli …` or `npm i -g eas-cli`.
- ⚠️ `build:ios` / `submit:android` auto-submit to stores; `push:update` publishes an OTA update to **production**. Do not run these from `claude`.

## 2. Analysis findings

### 2.1 Styling
- **111 files** each define their own `StyleSheet.create` — no shared style primitives.
- **186** literal `fontFamily: "OldStandard-..."` occurrences. The alias `OldStandard-*` actually loads **Barlow Condensed** (see `app/_layout.tsx`) — misleading name. `OldStandardTT-*` and `SpaceMono` font files are bundled but unused.
- **88** hardcoded hex colors outside `Colors.ts` (`#333`, `#333333`, `#1E1E1E`, `#CCCCCC`, `#FFFFFF`/`#ffffff`/`#fff` …) plus **18** named colors (`"red"`, `"white"`, `"grey"`). Same color written several ways.
- No typography or spacing scale: font sizes 13/14/15/16/18/20/22/25/28/32 used ad hoc.
- `constants/Colors.ts` has `light`/`dark` keys, but the app is dark-only; `light` and `ColorsHairSalon` are effectively dead. Key names are inconsistent (`borderColorDisabeld`, `textColor` vs `text`).
- Expo template theming (`Themed.tsx`, `ThemedText`, `ThemedView`, `useThemeColor`, `useColorScheme*`) exists but is not used by the app.

### 2.2 Component reusability
- `shared-components/` is a flat folder of ~55 files mixing primitives (button, input), domain cards (employer/service/location), screens (SplashScreen, SuccessScreen) and wrappers.
- **Overlapping variants of the same thing:**
  - Buttons: `Button.tsx` (unused), `SharedButton.tsx`, `SharedButtonDateReservation.tsx`, `SharedBackButton.tsx`, `CustomAppleButton`, `CustomGoogleButton`.
  - Inputs: `SharedInput` (handles text, password and phone via prop flags), `InputItem` (unused), `SharedPassword`, `SharedConfirmPassword`, `SharedPhoneNumber`, `SharedInputTextArea`, `SharedInputTextAreaMark`, `SharedNameEdit`.
  - Cards/items: `SharedItem`, `SharedItemEmployer`, `SharedItemEmployerCard`, `SharedEmployerCard`, `SharedDetailsEmployerCard`, `DetailsEmployer`, `SharedItemService`, `SharedItemServiceCard`, `SharedDetailsServiceCard`, `DetailsServices`, `SharedItemLocation` … (several unused).
  - Loaders: `components/Loader`, `components/LoaderDate`, `shared-components/SharedLoader` (modal overlay).
  - Reservation cards: `CardReservation`, `CardReservationItem`, `CardReservationPending`, `CardReservationRejected`, `CardNoReservation`.
- Good existing pieces worth keeping: `TouchableOpacity` (press-lock debounce), `withSafeArea` HOC (18 screens), `HeaderCoverImageContainer` (14 usages).

### 2.3 Logic reusability
- **Duplicated form hooks:** `useEmail` ×3, `usePassword` ×3, `useConfirmPassword` ×2 across login/register/forgotPass/changePass — each with slightly different validation (regexes copy-pasted, one uses `setTimeout` for validation without cleanup).
- **Duplicated fetch pattern:** every `useFetch*` hook re-implements `isLoading / error / data` + try/catch + `response.status === 200` check.
- **Navigation inside data hooks** (e.g. `useFetchServices` calls `router.push`) — mixes concerns.
- `helpers/index.js` (362 lines) is a grab-bag of date utilities with near-duplicates (`formatDateBrate` vs `formatDatePrettier`, month arrays repeated).
- API endpoints are string literals scattered in hooks/contexts.
- `apiService.js`: every method is `try { … } catch (e) { throw e }` (no-op); response interceptor returns `undefined` (instead of rejecting) when error has no `data.message` — network errors silently resolve.

## 3. Target architecture (proposed)

```
theme/
  colors.ts        semantic color tokens (background, surface, text.primary, text.muted, accent, danger, border …)
  typography.ts    font families + text variants (h1, h2, title, body, caption, button)
  spacing.ts       spacing scale (4-pt), radii, shadows
  index.ts         `theme` object + `useTheme()` hook
components/ui/     design-system primitives (no business logic)
  AppText, Button (variants: primary/secondary/ghost/social, loading, disabled),

  Screen (safe area + background + scroll), ScreenHeader / CoverHeader,

```

### 4.1 Build optimization plan (Phase 0.5, user request 2026-11-12)

Findings (2026-11-12, machine: 20 cores, 32 GB RAM, JDK 17, Android SDK `C:\Android\sdk`):
- ✅ Already optimal: `expo run:android` debug builds compile **only the connected device's ABI** (verified in `@expo/cli` `resolveGradlePropsAsync`), even though `gradle.properties` lists 4 ABIs. Use `--all-arch` only when needed.
- ✅ `org.gradle.parallel=true` already set by template.
- ❌ Gradle JVM heap only `-Xmx2048m` (machine has 32 GB) → GC pressure on Kotlin/C++ steps.
- ❌ Gradle **build cache off** (`org.gradle.caching` not set) → tasks re-run after `prebuild --clean`/branch switches.
- ❌ 4 native modules installed but **never imported**: `expo-device`, `expo-location`, `expo-haptics`, `expo-web-browser` → extra Kotlin compile + autolinking; `expo-location` also adds Play Services Location and location permissions to the manifest. (`expo-status-bar`, `expo-constants`, `expo-linking`, `react-native-screens`, `react-native-worklets`, `expo-system-ui`, `expo-updates` look unused but are required by expo-router/reanimated/config → keep.)
- ❌ `expo-doctor` (a CLI) is in `dependencies` → move to `devDependencies` (no native impact, hygiene).
- ⚠️ Windows Defender real-time scanning of `node_modules`, `android/`, `~/.gradle` is a common 1.5–2× slowdown on Windows (could not read exclusions without admin).

Steps:
| # | Step | Who | Expected effect |
|---|---|---|---|
| 1 | Measure baseline: clean build (`npx expo prebuild --clean` + `npm run android`) and no-change rebuild; record in metrics table | user/Claude | baseline |
| 2 | Local config plugin `plugins/withAndroidBuildSpeed.js` (survives `prebuild --clean`): `org.gradle.jvmargs=-Xmx6g -XX:MaxMetaspaceSize=1g`, `org.gradle.caching=true`; try `org.gradle.configuration-cache=true` and keep only if the build passes | Claude | faster Kotlin/C++ steps, cached tasks |
| 3 | Remove unused native modules (`expo-device`, `expo-location`, `expo-haptics`, `expo-web-browser`); move `expo-doctor` to devDeps | Claude | fewer native modules to compile; smaller APK; drops unused location permission |
| 4 | Windows Defender exclusions (admin PowerShell): project folder, `%USERPROFILE%\.gradle`, `%USERPROFILE%\.android`, `C:\Android\sdk`; optional: Windows 11 **Dev Drive** for project + Gradle cache | user | often largest single win on Windows |

| 6 | EAS: enable build cache in `eas.json` (`cache.key`) for Android profiles; optional larger `resourceClass` (paid) | Claude (+ user decides on paid) | faster cloud builds |
| 7 | Re-measure, record results | both | proof |
